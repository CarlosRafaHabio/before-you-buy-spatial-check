# H13 — killable callback in a separate synthetic subprocess

**2026-10-08 / PR #14 DRAFT / TEST ONLY / NO SECURITY PROMOTION**

H12 conclusively demonstrated that Monty's VM bytecode time budget and
an in-process monotonic check cannot terminate a blocking trusted
callback. H13 tests that missing property with a *real separate PID*,
without creating an actual API, privileged tool or OS sandbox.

Research: Python's documented Popen.communicate(timeout) raises
TimeoutExpired but leaves the child alive. The supervisor must kill
and reap it. In Linux/POSIX a new session+process group allows an
additional bounded test proving a non-detached descendant also stops.

H13 implementation:
- \`isolated_broker_worker_v0.py\`: a fixed, trusted executable with five
  predefined synthetic modes; no Python generated by an LLM or new
  dependency. The only irreversible evidence is a \`SYNTHETIC_EFFECT_V0\`
  line written into an isolated temporary test file by the worker.
- \`isolated_broker_v0.py\`: trusted caller selects fixed mode/absolute
  scratch path with bounded timeout, launches fresh Python with \`-I\`
  and explicit file path, minimal environment, no shell, no inherited
  unrelated descriptors, process session/group isolated. A timeout
  triggers SIGKILL for that group and reaps the leader. A crash, invalid
  response or timeout always returns UNKNOWN, never SUCCESS.
- Integration test routes Monty H12 guest through existing exact-scope
  G5 \`HostScopedUserLookup\`, with broker called *inside* callback.
  Host consumes authorization before spawn; timeout throws to G5 and
  reports \`HANDLER_OUTCOME_UNKNOWN\` rather than claiming a rollback.
- Tests also intentionally prove a host creating two independent
  gates can duplicate a synthetic effect: no durable authorization.

## Verified scope, NOT claimed

PROVES on Linux CI if all tests pass: killable direct separate process
and same-group descendants; fixed dispatch; callback and guest source
type/operation validation; original one-shot gate no automatic retry
for one gate; timeout can leave a committed synthetic effect.

DOES NOT prove: sandboxed worker; different OS UID; containment of
malicious Python executed in trusted host process; inability for a
grandchild to escape process group; kill process tree in arbitrary
environments; no FD delegation; durable per-tenant review authority,
signed epoch, provider idempotency, distributed exactly once, rollback,
or immunity to agent prompt injection.

A timed-out operation may already have side effects. Distinguish
BROKER_TIMEOUT_UNKNOWN from *no* side effect. Even after SIGKILL
returns and leader reaps, remote transactions may have committed.
Only external provider receipts/idempotency or reliable durable state
could resolve such ambiguity (out of scope).
